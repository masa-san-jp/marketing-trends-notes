## 空欄の読み方

- 空欄は「重要でない」ではなく **まだ手が届いていない**。
- 「調査したが、このカテゴリに該当するトレンドは無い」と判明したら、空欄のままにせず記録する。

  ```bash
  python3 tools/record_searched.py --market <カテゴリ> --geo <地理> \
      --scope "何を、どの範囲で探したか" --source <当たった出典URL>
  ```

  記録したカテゴリは計の欄が `0（調査済 n）` になり、表の下に何を探したかが出る。
  **未着手（ただの 0）と調査済みの 0 は別物**——調べ終わったところを何度も調べ直さないための区別。
  この記録は「次の調査をしなくてよい理由」になるので、`scope` が空の行と語彙外のカテゴリは検証が落とす。
- **鮮度切れ**の行は、載っているが再検証期限を過ぎたもの。件数が増えたら新規より先に再検証する。

## 需要から決める（探されたが無かった語）

生成ブロックの中に「探されたが無かった語」が出る。これは他の人格が `--search` で探して空振りした記録
（`data/queries.jsonl`）で、**需要のシグナル**として使う。回数が多い語は、被覆の空欄より先に埋める。

これが系を閉じるための線: 探される → 記録される → 表に出る → 埋める → 次は当たる。
記録が無ければ「書く→読まれる→何も返らない」の一方通行になる。

## 埋める順番（当面）

1. **自分の事業に直接触れるカテゴリ**から。判断材料にならないトレンドは後回しでよい
   （このKBの用途は網羅ではなく判断）。
2. **audit が指すもの**（鮮度切れ・vendor 単独・未判定の予測）。体系が次に要求していることなので、
   ただの空欄より優先度が高い。
3. **探されたが無かった語**。
4. 被覆マップの空欄。
